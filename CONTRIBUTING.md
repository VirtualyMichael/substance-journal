# Contributing

Thanks for helping. This is a harm-reduction tool, so correctness and honesty about uncertainty matter more than speed or polish.

## Reporting a problem

Open an [issue](../../issues) with what you did, what you expected and what happened, the platform and the app version (the release you installed, for example 2.0.0 preview).
**Never paste real journal entries.** If a screenshot helps, use made-up data.

## Correcting reference data

Dose, duration, tolerance and interaction numbers have the biggest effect on people, so they are held to a higher standard.

1. Say which compound, route and field is wrong.
2. Link the source you are relying on (PsychonautWiki, Erowid, TripSit, a paper). Two sources are better than one.
3. Where sources disagree, the conservative reading wins, and the disagreement is shown to the user rather than hidden.

The nine hand-audited compounds are set in `substance_journal/core/reference_overrides.py` (so a re-sync never reverts them) and documented in
[docs/data-audit](docs/data-audit/SUMMARY.md). The broad catalogue is regenerated by `scripts/sync_substance_data.py --extra`, and
`scripts/crosscheck_tripsit.py` compares it with TripSit.

## Code changes

- Set up with the steps in the [README](README.md#build-from-source). Run `flutter analyze` and all tests before opening a pull request: `flutter test`, `dart test` in `app/packages/sj_core`, and `python -m unittest discover tests`.
- Add a test with every change. UI tests use an in-memory database and real widget rendering; see `app/test/helpers.dart`.
- Keep user-facing wording plain and cautious. Never write that something is "safe", never tell someone it is fine to drive, and label estimates as estimates.
- Do not add anything that sends journal data off the device, adds an account, or phones home.
- Data that is stored must stay mergeable: every row is a UUID with a hybrid-logical-clock stamp and a tombstone flag, so sync and import cannot overwrite or resurrect edits.
